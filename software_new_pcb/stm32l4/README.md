# STM32L4 Firmware for the New PCB

This is the STM32CubeMX/CMake firmware project for the new STM32L431-based UWB PCB. It is the active software target for the migration from the old SKITH/DWM1000 platform to the new DWM3000-based board.

## Migration Context

| Layer | Legacy stack | New stack in this folder |
| --- | --- | --- |
| Hardware | SKITH board with DWM1000 | Tumbler PCB with DWM3000 family module |
| Microcontroller | STM32F407 | STM32L431 |
| Framework | RODOS and legacy wrappers | STM32Cube HAL |
| UWB driver | Decawave DWM1000 API | Qorvo DW3xxx driver |
| Application | Old tag/anchor firmware | New CubeMX firmware for the new PCB |

The goal is to keep the useful ranging protocol concepts from the old firmware while replacing the hardware-dependent layers with CubeMX/HAL and the Qorvo DW3xxx driver.

## Project Structure

| Path | Purpose |
| --- | --- |
| `stm32l4.ioc` | CubeMX project file. It defines the STM32L431 device, clock tree, peripherals, and pin names. |
| `Core/` | STM32CubeMX-generated application skeleton and HAL initialization code. |
| `Drivers/CMSIS/` | ARM/ST CMSIS support generated/copied by STM32CubeMX. |
| `Drivers/STM32L4xx_HAL_Driver/` | STM32L4 HAL driver sources from the STM32Cube firmware package. |
| `Drivers/dwt_uwb_driver/` | Local Qorvo DW3xxx driver sources used by this firmware. |
| `Drivers/dwt_uwb_src/` | Local Qorvo support/example source files used by the DW3xxx driver integration. |
| `platform/` | Board-port layer connecting the Qorvo driver to STM32 HAL SPI, GPIO, reset, wakeup, and IRQ functions. |
| `Communication/` | Early send/receive helper functions for DW3xxx frame exchange. |
| `cmake/` | Toolchain and CubeMX CMake integration files. |
| `CMakeLists.txt` | Main firmware build definition. |

## CubeMX Pin Mapping

CubeMX translates the physical PCB wiring into generated C symbols. The important firmware-facing signals are:

| MCU pin | CubeMX label | Role |
| --- | --- | --- |
| `PA0` | `DWM_IRQ` | Interrupt from the UWB module. |
| `PA4` | `SPI1_NSS` | Software-controlled chip select for SPI. |
| `PA5` | `SPI1_SCK` | SPI clock. |
| `PA6` | `SPI1_MISO` | SPI data from DWM3000 to STM32. |
| `PA7` | `SPI1_MOSI` | SPI data from STM32 to DWM3000. |
| `PB0` | `EXTON` | External enable/control signal. |
| `PB1` | `WAKEUP` | Wakeup signal for the UWB module. |
| `PB2` | `DWM_nRST` | Reset line for the UWB module. |
| `PA9` | `BMS_SCL` | I2C clock for battery-management communication. |
| `PA10` | `BMS_SDA` | I2C data for battery-management communication. |

The PCB is the electrical source of truth. CubeMX mirrors that wiring, and the generated names are then used by `platform/port.c` so the Qorvo driver can access the real SPI and GPIO lines.

## Driver Integration

The Qorvo driver is not generated by CubeMX. The full DW3xxx/QM33 SDK is not stored as a separate folder in this repository; only the driver and support sources needed by this firmware are kept locally:

- `Drivers/dwt_uwb_driver/`
- `Drivers/dwt_uwb_src/`

The local project glue is mainly in:

- `platform/port.c`
- `platform/port.h`
- `platform/dw3000_config.c`
- `platform/dw3000_config.h`
- `Communication/communication.c`
- `CMakeLists.txt`
- `Core/Inc/main.h`
- `Core/Src/main.c`

## Build

```shell
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=cmake/gcc-arm-none-eabi.cmake -DCMAKE_UWB_CONFIG_OPTION=5
cmake --build build
```

## Flash

Flash the ELF with an ST-Link:

```shell
st-flash --reset write build/stm32l4.elf 0x8000000
```

If the `st-flash` version has issues with ELF flashing, convert the output to a binary first:

```shell
arm-none-eabi-objcopy -O binary build/stm32l4.elf build/stm32l4.bin
st-flash --reset write build/stm32l4.bin 0x8000000
```

## Debug

Start OpenOCD in one terminal:

```shell
openocd -f /usr/share/openocd/scripts/interface/stlink-v2.cfg -f /usr/share/openocd/scripts/target/stm32l4x.cfg
```

Open GDB in another terminal:

```shell
gdb build/stm32l4.elf
```

Connect to the OpenOCD GDB server:

```shell
target extended-remote localhost:3333
```

## Bring-Up Path

The recommended order is:

1. Confirm the CubeMX pin map against `../../Tumbler_new_PCB/`.
2. Validate SPI chip-select, reset, wakeup, and IRQ behavior in `platform/port.c`.
3. Read the DW3xxx device ID through the Qorvo driver.
4. Send and receive a raw UWB frame.
5. Port the old tag/anchor protocol from `../../old_uwb_reference_repo/embedded_uwb/`.
6. Calibrate antenna delays and timing on the new PCB.

This keeps the migration clean: protocol logic is reused, but the hardware driver and board layer are native to the new DWM3000/STM32L431 platform.
