# UWB Hardware and Firmware Migration

This repository organizes the hardware, power-analysis, embedded-driver, and firmware assets used to migrate an academic UWB localization node from the older SKITH/DWM1000 platform to a newer STM32L4/DWM3000 PCB.

The project is intentionally split by layer. The legacy folders are kept as engineering references, while the new CubeMX firmware and the Tumbler PCB are the active migration target.

## Project Context: AMADEE-27

This work was developed in the context of a university robotics project preparing a contribution for AMADEE-27, an international Mars analog mission managed by the Austrian Space Forum (OeWF).

AMADEE-27 is designed to emulate selected aspects of a human-robotic Mars mission. The mission concept combines analog astronauts, robotic systems, field experiments, and a Mission Support Center in Austria to recreate operational constraints similar to planetary exploration. The official AMADEE-27 call focuses on areas such as engineering and robotics, planetary surface operations, geoscience, life sciences, and human factors.

Within that broader university project, my responsibility was the Tumbler UWB subsystem: understanding the old UWB localization stack, migrating the hardware/firmware concept from DWM1000 to DWM3000, documenting the PCB and power-budget context, and preparing the new STM32CubeMX/HAL firmware structure for the upgraded PCB.

## Migration Summary

| Layer | Legacy platform | New platform |
| --- | --- | --- |
| Hardware | DWM1000-based SKITH board | DWM3000-based Tumbler board |
| Microcontroller | STM32F407 | STM32L431 |
| Framework | RODOS and legacy board wrappers | STM32Cube HAL generated by CubeMX |
| UWB driver | Decawave DWM1000 API | Qorvo DW3xxx driver |
| Application | Legacy tag/anchor ranging code | New CubeMX firmware for the new PCB |

## What Is Reused

The useful software inheritance is at the protocol level, not at the low-level driver level. The legacy code is valuable because it already contains the tag/anchor ranging flow, message types, timestamp packing, and two-way-ranging state machine. Those concepts can be ported to the new firmware.

The old Decawave DWM1000 driver, the RODOS scheduling code, the old SPI/GPIO wrappers, and the old board calibration constants should not be copied directly into the new STM32L431/DWM3000 firmware.

## Current Engineering Focus

The new firmware is built around STM32Cube HAL and the Qorvo DW3xxx driver. CubeMX describes the real wiring from the new PCB, including SPI, IRQ, reset, wakeup, power-control, and BMS-related pins. The firmware then uses those generated names in the board-port layer so that the UWB driver can talk to the DWM3000 through the actual hardware connections.

The practical bring-up path is:

1. Validate the CubeMX pin map against the Tumbler PCB schematic.
2. Bring up SPI, reset, wakeup, chip-select, and IRQ in the STM32 port layer.
3. Read the DW3xxx device ID through the Qorvo driver.
4. Test raw TX/RX frames.
5. Port the old tag/anchor ranging logic onto the new driver and HAL base.
6. Recalibrate antenna delays and timing for the new board.

## Engineering Highlights

This repository demonstrates a full embedded migration across hardware, firmware, and tooling boundaries:

- translating real PCB wiring into CubeMX/HAL pin definitions,
- replacing a legacy DWM1000 driver stack with the Qorvo DW3xxx driver,
- separating reusable ranging logic from non-reusable board/framework code,
- keeping only the required DW3xxx driver sources inside the firmware tree instead of storing the full vendor SDK,
- connecting firmware operating modes to spreadsheet-based power estimates.

## Notes for Reviewers

This repository is a migration and integration workspace, so it intentionally contains both original references and new implementation work. The separation is important: hardware design files document the boards, the power spreadsheets document expected operating modes, and the CubeMX firmware is where the new embedded software and DW3xxx driver integration are implemented.
